# Codex 账号池化设计

首版 Codex CLI 和 Claude Code 的端点都可以绑定到同一个 Codex OAuth 账号池。账号池由独立的 `agent-forwarder` 应用承载，`agent-gateway` 通过内部双向流调用它。本文定义账号选择、额度、凭据和跨副本行为。系统拓扑、用户端点配置和端到端请求流程见 [系统架构与请求流程](architecture.md)。

## 2. 账号调度和额度

1. **先筛资格。** 在端点指定的账号池内，按调用用户的权限、模型和传输能力筛选，再排除停用、待重登及相应范围仍在冷却的账号。无可用并发槽时只进入有上限的等待队列。
2. **已有会话先看原账号。** 原账号健康且可用时继续使用。短暂繁忙时在请求预算内等待。确需换号时，由轮次执行器判断能否安全续接。新账号成功承接该轮后再更新绑定。
3. **新会话按额度和负载选。** 优先选择有容量的账号，在同档内用当前并发和稳定散列打破平局。缺少额度数据时标为未知，按有限预算安排重新采样和探测。账号额度由最近有效快照决定，过期后转为未知。
4. **合并额度信号。** 被动读取成功响应和限流响应中的额度信息，并用有并发上限和退避的后台查询覆盖空闲账号。记录每个额度窗口的利用率、重置时间、采集时间和作用范围。旧数据不能覆盖更新的观察，采样失败不能清除已确认的冷却。

选路时原子申请用户和上游账号两级并发槽。同一用户的多个端点共用用户级上限，使用同一上游账号的请求共用该账号的上限。成功、错误、取消和超时都要释放，等待队列和请求预算共用取消信号。连接空闲时释放推理槽，每轮重新确认端点授权和可用容量。账号租约在 `agent-forwarder` 内申请，用户侧预检和账单窗口由 `agent-billing` 管理，两者使用不同的租约标识。

## 3. 会话、故障切换与错误语义

### 提交边界

自动换号只发生在轮次尚可安全重放时。代理转发第一个有业务语义的事件前，检查上游易于识别的拒绝事件。首个业务事件可以是已发布的响应 ID、正文、推理或工具调用。一旦提交，后续故障按原协议终止该轮，由客户端续接。对于可能已经触发上游托管工具等副作用的请求，只有上游明确拒绝执行或具备可验证的幂等语义时才允许自动重放。

`previous_response_id` 可能依赖原账号和原连接。代理按用户、端点、路由版本和账号池隔离会话与响应归属，并检查续接条件。只有请求本身提供足够的可移植上下文、且适配器确认当前轮可重放，才允许在该端点绑定的池内跨账号恢复。其余场景返回客户端能识别的续接错误。代理仅持久化绑定元数据，完整输入和输出随轮次结束释放。对流式 HTTP 使用有限的首段检查预算，流已经提交后使用协议终止事件报告错误。WebSocket 同样按轮次划分边界。

### 失败分类

| 情况 | 处理 |
| --- | --- |
| 上游返回凭据失效 | 比较本轮使用的凭据版本，优先采用已刷新的令牌。需要刷新时同账号合并请求。刷新后最多对当前账号重试一次，永久失效则标为待重登。 |
| 账号额度耗尽 | 冷却账号直到可靠的重置时间。当前轮可重放时，在剩余预算内选其他账号。 |
| 单模型限流 | 只冷却对应账号和模型，保留同一账号的其他模型。 |
| 网络失败或上游过载 | 按适配器判定做有限重试或临时退避。短暂连接故障和配额耗尽使用不同的状态。 |
| 参数、模型或调用方权限错误 | 直接返回客户端可处理的错误。模型返回和替代账号均须满足原请求的能力要求。 |
| 所有可用范围内的账号均受额度限制 | 返回 `429`。下一次可尝试时间可靠时带上 `Retry-After`。 |
| 合法请求当前缺少健康账号 | 返回 `503`，输出明确的错误类型，供调用方识别短暂不可用。 |

提交轮次前的排队、上游尝试、刷新和换号共用一个有界预算。正常长流采用单独的空闲超时和连接保活。监听客户端取消，及时停止上游请求并释放并发槽。并发等待、首段缓冲和 WebSocket 消息大小都设可配置的上限。

## 4. 共享状态与凭据

| 组件 | 职责 |
| --- | --- |
| MySQL | 账号、加密凭据、凭据版本与刷新所有权、端点与客户端 Key、账号和模型冷却、配额快照、带有效期的会话与响应索引、用量记录。关键更新从主库读写。 |
| Redis | 跨副本的并发租约和等待通知，缓存会话索引及账号状态版本，协调定时任务去重。缓存缺失时从 MySQL 恢复。 |
| 代理进程 | 保存当前 HTTP 流、WebSocket 和本轮重放判断所需的临时信息。副本之间共享的是会话索引和池状态。 |

MySQL 是持久化状态的权威来源。停用账号、撤销访问、更新冷却和会话归属时先提交 MySQL，再更新或失效缓存。授权、账号资格和响应归属在使用时校验当前状态，缓存无法确认时读取主库。使用版本及有效期处理缓存更新乱序，重启后按 MySQL 记录恢复仍有效的冷却。

### 数据模型

| 记录 | 主要字段与约束 |
| --- | --- |
| 调用方与客户端密钥 | 用户、端点 ID、密钥摘要、作用范围、撤销状态。密钥高熵生成，明文只在创建时展示。 |
| 上游账号和凭据 | 上游、账号池、上游账号标识、状态、加密凭据、到期时间、凭据版本、刷新所有者和刷新状态。按上游账号身份去重。 |
| 冷却与额度快照 | 账号、模型或额度窗口、观测时间、重置时间和错误分类。持久化更新时拒绝旧观测覆盖新状态。 |
| 会话与响应索引 | 用户、端点 ID、路由版本、账号池、上游、会话或响应标识、绑定账号、有效期。响应归属仅对当前端点及路由版本可查。 |
| 用量和尝试记录 | 请求 ID、用户、端点 ID、模型、账号、尝试序号、结果、延迟和上游确认的用量。按请求和轮次去重结算。 |

### 跨副本 OAuth 刷新

1. 副本在 MySQL 中按账号和凭据版本原子认领一次刷新，再调用上游。其他副本使用仍有效的凭据，或在请求预算内等待并重读。后台刷新和 401 触发的刷新共享同一个入口。
2. 刷新成功后按刷新所有者和旧版本条件写入新凭据。上游已轮换而数据库暂时写入失败时，原刷新者保留新结果并在有界时间内重试持久化，期间暂停该账号的新请求。
3. 刷新超时或持有副本退出，且上游是否已轮换无法确认时，状态转为待确认并停止调度。通过重新授权恢复账号。旧副本迟到的写入由所有者和凭据版本校验拒绝。

### 并发租约和依赖故障

Redis 用原子操作申请用户侧和账号侧并发租约。租约有唯一所有者、应用标识和有效期，长轮次续租，结束时只释放本轮持有的槽位。实例崩溃后的槽位由过期清理回收。`agent-forwarder` 使用账号租约，`agent-billing` 使用额度窗口租约，不能互相释放。首版使用单个逻辑 Redis 主写端点，确保每个应用内部的租约申请可在同一次原子操作内完成。

无法确认 Redis 租约时暂停新轮次。持续续租失败的活跃轮次在本地租约到期前终止并取消上游。检测到 Redis 主从切换或租约状态丢失后，先隔离旧租约并等待租约窗口结束，再恢复调度。Redis 异步故障转移期间的全局严格并发上限需要由持久化协调器保证。MySQL 主库无法确认授权和账号状态时，代理以有界等待和 `503` 处理新请求。

## 5. 池化验收

1. 两个副本同时遇到同一个过期令牌时，只发起一次刷新。刷新者在上游返回后、MySQL 提交前退出时，账号进入待确认，重新授权后恢复。迟到的刷新写入无法覆盖新凭据。
2. A 账号额度耗尽后，另一副本观察到冷却，可安全重试的请求切到 B。模型级冷却只影响对应模型，代理重启后仍有效。验证额度采样失败、观测过期、额度档变化和空闲账号恢复。
3. 验证新会话按额度和负载分流、已有会话优先走原账号，以及跨副本命中同一绑定。验证依赖原连接的续接，以及不同用户、端点和路由版本之间的响应索引隔离。
4. 分别在首个业务事件之前和之后注入断流，验证提交前的安全换号、提交后的协议终止和工具调用无重复。用有状态续接和自包含输入分别验证 compact 的选号行为。
5. 双副本制造跨实例并发竞争、实例退出、Redis 故障转移、MySQL 短时不可用和全池额度耗尽。验证请求在预算内退出，租约可以回收，后续请求可恢复，用量只结算一次。
